## Overview

Every model in this course has been checked with `.score()` — accuracy.
Accuracy is often the wrong metric. Consider a fraud detector where only
0.5% of transactions are actually fraudulent: a model that predicts "not
fraud" for *everything* scores 99.5% accuracy while catching zero fraud.
This lesson covers the metrics that actually reveal what's going on.

## The confusion matrix

Every binary classification metric is derived from four counts:

|  | Predicted positive | Predicted negative |
|---|---|---|
| **Actually positive** | True Positive (TP) | False Negative (FN) |
| **Actually negative** | False Positive (FP) | True Negative (TN) |

- **Precision** = `TP / (TP + FP)` — of everything the model flagged as
  positive, what fraction actually was? High precision means few false
  alarms.
- **Recall** = `TP / (TP + FN)` — of everything that actually was positive,
  what fraction did the model catch? High recall means few misses.

These two trade off against each other. A model can trivially get 100%
recall by flagging everything as positive (catches every real case, but
drowns you in false alarms) or high precision by only flagging its most
confident cases (few false alarms, but misses many real ones).

## F1 score: balancing precision and recall

**F1** is the harmonic mean of precision and recall:

```
F1 = 2 · (precision · recall) / (precision + recall)
```

The harmonic mean (rather than a simple average) specifically punishes
having one metric much lower than the other — a model with 100% precision
and 1% recall gets an F1 near 2%, not 50%. F1 is a good single-number
summary when you care about both false positives and false negatives
roughly equally, and especially useful on imbalanced datasets where
accuracy is misleading.

## ROC-AUC: threshold-independent evaluation

Every metric above depends on a classification *threshold* (usually 0.5).
**ROC-AUC** evaluates the model across *every possible threshold* at once,
plotting true positive rate against false positive rate and measuring the
area under that curve. AUC = 1.0 is a perfect classifier; AUC = 0.5 is no
better than random guessing. It's especially useful for comparing models
independent of where you'll eventually set the decision threshold.

## In real code

<PyodidePlayground initialCode={`import numpy as np
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import (
    accuracy_score, precision_score, recall_score, f1_score, roc_auc_score
)

# Deliberately imbalanced: 95 negative, 5 positive.
rng = np.random.RandomState(0)
X_neg = rng.normal(0, 1, size=(95, 2))
X_pos = rng.normal(3, 1, size=(5, 2))
X = np.vstack([X_neg, X_pos])
y = np.array([0] * 95 + [1] * 5)

model = LogisticRegression().fit(X, y)
y_pred = model.predict(X)
y_proba = model.predict_proba(X)[:, 1]

print("Accuracy:", round(accuracy_score(y, y_pred), 3))
print("Precision:", round(precision_score(y, y_pred), 3))
print("Recall:", round(recall_score(y, y_pred), 3))
print("F1:", round(f1_score(y, y_pred), 3))
print("ROC-AUC:", round(roc_auc_score(y, y_proba), 3))

# Compare against a dummy model that always predicts "negative".
always_negative = np.zeros_like(y)
print("\\nAlways-negative baseline accuracy:", round(accuracy_score(y, always_negative), 3))
`}
/>

Notice the "always predict negative" baseline still scores high accuracy
despite being useless — exactly the trap this lesson opened with. Precision,
recall, and F1 expose that uselessness immediately.
