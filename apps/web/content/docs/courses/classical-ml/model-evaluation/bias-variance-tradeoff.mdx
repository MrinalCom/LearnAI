## Overview

Every lesson in this course has quietly circled the same idea: KNN's `k`,
decision trees' `max_depth`, SVMs' `C`, k-means' `k` — each is a knob that
trades off the same two failure modes. This lesson makes that tradeoff
explicit and names it properly: **bias vs. variance**.

## Why you can't just check training accuracy

If you evaluate a model on the same data it was trained on, you're not
measuring how well it learned — you're measuring how well it *memorized*.
A model can achieve 100% training accuracy while being completely useless on
new data (this is exactly what an unconstrained decision tree does). The
fix is a **train/test split**: hold out a portion of your labeled data
(commonly 20-30%), train only on the rest, and evaluate only on the held-out
set the model never saw.

## Bias and variance, defined

- **Bias** is error from a model being *too simple* to capture the real
  pattern — it makes systematically wrong assumptions regardless of how
  much data you give it. A high-bias model **underfits**: poor performance
  on both training and test data.
- **Variance** is error from a model being *too sensitive* to the specific
  training data it saw — it fits noise, not signal. A high-variance model
  **overfits**: great training performance, poor test performance.

Total error is (roughly) `bias² + variance + irreducible noise`. You cannot
drive both bias and variance to zero simultaneously by tuning a single
model's complexity — reducing one typically increases the other. Every
"complexity knob" you've met so far controls exactly this tradeoff:

| Model | Low complexity (high bias risk) | High complexity (high variance risk) |
|---|---|---|
| KNN | large `k` | `k = 1` |
| Decision tree | shallow (`max_depth=2`) | unconstrained |
| SVM | small `C` | large `C` |
| Linear/logistic regression | fewer features | many features, no regularization |

## Seeing it directly

<PyodidePlayground initialCode={`import numpy as np
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier

rng = np.random.RandomState(0)
X = rng.uniform(0, 10, size=(200, 2))
y = ((X[:, 0] + X[:, 1]) > 10).astype(int)
# Flip 10% of labels to simulate real-world noise.
flip = rng.choice(len(y), size=len(y) // 10, replace=False)
y[flip] = 1 - y[flip]

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=0)

for depth in [1, 3, None]:
    clf = DecisionTreeClassifier(max_depth=depth, random_state=0)
    clf.fit(X_train, y_train)
    train_acc = clf.score(X_train, y_train)
    test_acc = clf.score(X_test, y_test)
    label = depth if depth else "unlimited"
    print(f"max_depth={label}: train acc={train_acc:.2f}, test acc={test_acc:.2f}")
`}
/>

Watch the gap between train and test accuracy widen as `max_depth` grows —
that growing gap *is* variance (overfitting) in action.
